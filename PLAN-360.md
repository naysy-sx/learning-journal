## Фаза 2 — Идентичность и криптография

**Длительность:** 8 недель (~160 часов)

### Что строим в проекте

- `identity.js` — генерация keypair (secp256k1), NIP-06 деривация из мнемоники BIP-39
- `keystore.js` — зашифрованное хранилище приватного ключа (PBKDF2 + AES-GCM)
- `crypto.js` — NIP-44 шифрование (ECDH + HKDF + ChaCha20-Poly1305)
- `nip59.js` — NIP-59 Gift Wrap: rumor → seal → gift wrap
- `validators.js` — validateEventId (SHA-256 канонического JSON), verifySig (Schnorr BIP-340); события не прошедшие проверку отбрасываются (F-EV-01..03)
- `crypto.worker.js` — batch-verify подписей через Comlink, изолированно от UI-потока (F-EV-04)
- Экран онбординга: три варианта — создать аккаунт (A), войти по мнемонике (B), войти по nsec через NIP-19 decode (C)

**Критерии приёмки (из ТЗ):** AC-01, AC-03.

### Розен (математика)

**Главы 2, 3, 4**

| Глава | Раздел                                      | Зачем                                                                                                                 |
| ----- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 2     | Множества, функции                          | Event Store = множество. G-Set merge = объединение множеств (∪). Хеш-функция — математическая функция                 |
| 2     | Последовательности, мощность                | Канонический JSON — последовательность байтов. Мощность 2²⁵⁶ — почему коллизии SHA-256 невозможны на практике         |
| 3     | Алгоритмы, рост функций, сложность          | Формальная база О-нотации (уже знакомой из Венгроу). Классы P и NP: почему подпись создаётся за мс, а взломать нельзя |
| 4     | Делимость, модулярная арифметика            | **Сердце фазы.** secp256k1 работает в F_p — поле по простому модулю                                                   |
| 4     | Простые числа, НОД, расширенный Евклид      | Основа умножения точек на кривой. Обратный элемент в F_p                                                              |
| 4     | Решение сравнений                           | Подпись Schnorr использует обратный элемент. Понять — значит уметь отладить                                           |
| 4     | Криптография (RSA, DH, дискретный логарифм) | После этого раздела ECDH и NIP-44 становятся прозрачными                                                              |

**Практика:** реализовать на JS: `gcd`, расширенный `gcd`, быстрое возведение в степень по модулю (`fastModPow`), тест простоты Миллера–Рабина (упрощённый), пример RSA на маленьких числах.

### Венгроу (алгоритмы)

- Стеки и очереди — Outbox (фаза 3) это очередь; стек вызовов async/await
- Введение в рекурсию — распаковка gift wrap рекурсивна: giftWrap → seal → rumor
- Написание рекурсивного кода — техники: базовый случай, шаг индукции

**Практика:** реализовать `fastModPow` рекурсивно и итеративно. Реализовать `unwrap` NIP-59 как одну рекурсивную функцию.

### Фрисби (JavaScript)

- Промисы и асинхронные функции — Web Crypto API полностью асинхронный
- Функции: замыкания, `this`, `bind`, стрелочные — замыкания для хранения сессий ECDH
- JSON — канонический JSON для event id (порядок ключей важен, `JSON.stringify` не гарантирует)
- API в JavaScript: Web Crypto API, `TextEncoder/Decoder`, `crypto.getRandomValues`
- Ссылочные типы коллекций: `Uint8Array`, `ArrayBuffer`, `DataView` — все крипто-функции работают с байтами
- Прокси и Reflect — опционально, для понимания Signals в Preact

## Фаза 3 — Транспорт и синхронизация

**Длительность:** 8 недель (~160 часов)

### Что строим в проекте

- `relay-pool.js` — WebSocket-пул из 3 соединений, round-robin, XState автомат (таблица 9.3 ТЗ), exponential backoff
- `publisher.js` — публикация события, ожидание OK/ERROR от relay, retry
- `subscriber.js` — подписка по фильтрам, обработка EOSE, батчинг записи в IndexedDB (100–200 мс)
- `outbox.js` — персистентная очередь в IndexedDB, drain при событии `online`, идемпотентность
- `lamport.js` — логические часы: `tick()`, `receive()`, `initFromHistory()`, `persist()`
- `cold-start.js` — процедура восстановления: download → validate → decrypt → fold → views → lamport
- `incremental-sync.js` — синхронизация с `lastSeen`, прогресс-индикатор
- Публикация kind 0 (профиль) и kind 10002 (relay list)

**Критерии приёмки (из ТЗ):** AC-02 (частично), AC-09, AC-10, AC-12.

## Принцип всего плана

> Теория изучается **непосредственно перед** тем, как она нужна в коде.

Не «изучи всю математику, потом кодируй» и не «кодируй всё подряд». Каждая глава имеет конкретный адрес в проекте: теория чисел — для криптографии в фазе 2, автоматы — для XState в фазе 5, деревья — для комментариев в фазе 6.

Если фаза завершена — значит и теория пройдена, и код написан, и критерии приёмки выполнены.
